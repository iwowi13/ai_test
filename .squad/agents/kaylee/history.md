- **Step 9 (2026-05-20):** Auth endpoints shipped. `POST /auth/register` (201, 409 on dup, 422 on validation) and `POST /auth/login` (200 with `{access_token, token_type:"bearer"}`, 401 on bad creds — same status for unknown-email and wrong-password to avoid user enumeration). Layout: `app/schemas/auth.py` for Pydantic I/O (RegisterIn/LoginIn/UserOut/TokenOut), `app/routes/auth.py` with `APIRouter(prefix="/auth", tags=["auth"])`, mounted via `app.include_router(auth_router)` in `main.py`. New `app/schemas/` and `app/routes/` packages (empty `__init__.py` markers). 6 new tests in `tests/test_auth_endpoints.py` use a `fresh_email` fixture (uuid4-based) that deletes the row in teardown so the dev DB stays clean. **Gotcha — `pydantic[email]`:** `EmailStr` requires the `email-validator` package; not transitively pulled by anything else, so I added `pydantic[email]>=2.0` to deps and reran `pip install -e .[dev]`. Final: 18/18 pytest green.
- **Steps 10, 11, 12, 13 (2026-05-20):** Auth-dep + full posts API + image upload.
  - **Step 10 (`6b2cee0`):** `app/deps.py::get_current_user` uses `OAuth2PasswordBearer(tokenUrl="/auth/login", auto_error=False)` so missing token → 401 (not 403), then `decode_access_token` → load `User` by `sub` (user id as string). `GET /auth/me` returns `UserOut`. 4 tests (no token / bad token / valid / unknown user).
  - **Step 11 (`379207d`):** Public reads. `app/routes/posts.py` with `GET /posts` (list, ordered by `created_at DESC`) and `GET /posts/{id}` (404 if missing). `PostOut` schema + `from_attributes=True` so SQLModel rows serialize cleanly. 3 tests.
  - **Step 12 (`3bc4495`):** Protected writes. `POST /posts` (201), `PATCH /posts/{id}` (partial via `model_dump(exclude_unset=True)`, refreshes `updated_at`), `DELETE /posts/{id}` (204). Helpers: `_slugify` (lowercase + non-alphanum→`-`, fallback `"post"`), `_unique_slug` (appends `-2`, `-3`, ... on collision), `_get_or_404`, `_require_author` (403 vs 404 — fetch first, then check ownership, so a missing post is always 404 regardless of auth). 7 tests covering create / patch / delete / 401 / 403 / 404 / slug collision.
  - **Step 13 (`90c5eb6`):** Image upload. `POST /posts/{id}/image` accepts `UploadFile` (multipart `file` field), validates `content_type.startswith("image/")` → 400 otherwise, streams in 64 KB chunks with running total → 413 over 5 MB (deletes partial file). Saves to `backend/uploads/{id}{ext}` (ext from `mimetypes.guess_extension`, `.jpe`→`.jpg`); stores public path `/uploads/{id}{ext}` in new `Post.image` column. Migration `d1d533cd24c6` adds the nullable `image` column. `StaticFiles` mount at `/uploads` in `create_app()`, with `uploads_dir.mkdir(exist_ok=True)` so fresh checkouts boot. `backend/uploads/.gitkeep` committed; `backend/uploads/` ignored. New dep `python-multipart` (FastAPI needs it for `UploadFile`). 4 tests (no auth / wrong user / success / non-image rejected) — fixture cleans up uploaded files on disk too. **Gitignore additions:** `_commit-msg-*.txt` and `*_commit-msg-*.txt` so stray commit-message scratch files can't be committed.
  - **Pattern notes:** ownership-check order matters (`_get_or_404` before `_require_author` keeps 404 > 403 priority). All write endpoints take `current_user: User = Depends(get_current_user)` — no manual header parsing anywhere. `PostOut.model_config = {"from_attributes": True}` is the bridge from SQLModel rows to Pydantic response.
